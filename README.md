# IPL Data Analysis (2008–2024)

End-to-end analysis of **17 IPL seasons** — 1,095 matches and 260,920 ball-by-ball deliveries — using Python, SQL (SQLite), statistical testing and interactive dashboards.

The goal is not just to describe the data but to show how cleaning decisions, sample sizes and significance tests change the conclusions.

**Explore it:** open `dashboard.html` in a browser and filter by season range, team and venue sample size.

## Highlights

| Question | Answer | Why it is more than a number |
|----------|--------|------------------------------|
| Most wins | **Mumbai Indians — 144** | Raw wins reward teams that played more seasons |
| Best win % | **Gujarat Titans ~62%** (45 matches); **CSK ~58%** (238 matches) is the best among long-running franchises | Small samples inflate percentages, so rankings show the match count |
| Consistency in finals | **CSK: 10 finals in 15 seasons (66.7%), 5 titles**; Mumbai Indians: 6 in 17 (35.3%), 5 titles | CSK did not play in 2016–17 (suspension), so raw totals understate its rate. Rajasthan Royals missed the same seasons and reached 2 finals |
| Does winning the toss help? | **No** — toss winners won 50.8% of matches (chi-square p = 0.52) | Consistent with a coin flip |
| Does the toss *decision* matter? | **Yes** — toss winners who chose to field won 53.9% vs 45.4% for bat (+8.5 points, 95% CI 2.3 to 14.6, chi-square p = 0.009) | The blended 50.8% hides this split. Observational: captains choose by conditions the data does not record |
| Top run-scorer | **V Kohli — 8,014** (973 in 2016 is the best single season) | DA Warner topped three seasons, Kohli two |
| Highest strike rate (min. 1,000 balls) | **AD Russell — ~174.8** | The minimum-balls rule stops one-ball cameos topping the list |
| Top wicket-taker | **YS Chahal — 205** | Run-outs and retirements are not credited to bowlers |
| Most six-friendly venue (over 20 matches) | **M Chinnaswamy Stadium — 14.9 sixes/match** | Venues with only a few matches reached 17+ and were excluded as unreliable |

## Data cleaning decisions

Every fix was checked after applying it, and several came from verification catching a mistake:

| Issue | Decision | Reason |
|-------|----------|--------|
| `season` text such as `2007/08` | Derive the year from `date` | Slicing the first 4 characters silently merged the 2009 and 2010 seasons |
| Spelling drift (Bangalore/Bengaluru, Supergiant/Supergiants) | Merge | Same team, different text |
| Franchise rebrands (Delhi Daredevils → Capitals, Kings XI → Punjab Kings) | Merge | Continuous franchise history |
| Deccan Chargers vs Sunrisers Hyderabad | Keep separate | Different franchises, not a rename |
| Venue names (`Wankhede Stadium, Mumbai`, renamed grounds) | Strip city suffix, map renamed grounds | One ground had up to three labels |
| Team names in `deliveries.csv` | Clean separately | Cleaning one file does not clean the other |
| Missing `city` (UAE venues) | Fill from `venue` | The true value was recoverable |
| Missing `winner` (no-result matches) | `"No Result"`, excluded from win calculations | Not a real team |
| Missing `method` | `"Normal"` | Blank only means the match was not rain-affected |
| Ties / no-result margins and targets | `-1` placeholder in the notebook, real NULL in the exported tables | Placeholders must never reach an average |
| `match_type` finals | Exact match on `Final` | `Semi Final` and `Elimination Final` also contain the word "Final" |

## Method

```text
Raw CSVs -> inspection -> cleaning -> EDA (pandas) -> SQL (CTE, window functions)
         -> hypothesis tests (SciPy chi-square) -> visualisation -> dashboards -> findings
```

| Tool | Used for |
|------|----------|
| pandas, NumPy | loading, cleaning, aggregation |
| SQLite3 | joins, `HAVING`, CTE + `RANK()` window function |
| SciPy | chi-square tests (toss, toss decision) |
| matplotlib, seaborn | static charts, each chosen for the question it answers |
| Plotly | `dashboard.html` and `dashboard_overview.html` |
| Power BI | optional dashboard, built from the notebook's export |

## How to run

```bash
pip install -r requirements.txt
jupyter notebook ipl_final.ipynb
```

Run all cells from the top (Kernel → Restart & Run All). The run also writes `dashboard_overview.html`, `ipl.db`, the `powerbi/` tables and the interactive `dashboard.html`.

To rebuild only the interactive dashboard after the notebook has run once:

```bash
python build_dashboard.py
```

The dashboards load Plotly from a CDN, so open them with an internet connection.

## Dashboard

`dashboard.html` has three filters (season range, team, minimum venue sample size) and eight panels: win % by team, matches per season, toss decision, sixes per match by venue, top run scorers, top wicket takers, top scorer of each season, and venues by matches hosted. Small samples are greyed out or filtered rather than ranked as if they were reliable.

See [POWER_BI_GUIDE.md](POWER_BI_GUIDE.md) for the data model, Power Query M, DAX measures, a four-page layout, the theme in `powerbi_kit/IPL_Theme.json`, and a checklist of numbers the report must reproduce.

## Limitations

- The dataset has no pitch, weather, dew or day/night fields, so explanations for the toss-decision effect are hypotheses, not findings.
- Win percentages for newer franchises (Gujarat Titans, Lucknow Super Giants) rest on small samples.
- The toss-decision result is observational and does not show that fielding causes wins.
